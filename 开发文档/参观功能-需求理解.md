# 参观功能 — 需求理解与本期实现

## 1. 一句话

用户付一笔**押金**购买「参观卡」，在有效期内可到**下单时选中的那一家门店**刷脸参观一次；进店后按**可参观时长**计时，按时离店则**原路退回押金**，超时则**全额扣除押金**；买了从未进店可主动退款，到期未进店系统自动退。

正式会员卡仍**不可退款**；参观押金退款走单独通路。

---

## 2. 已拍板规则

| 项 | 结论 |
| --- | --- |
| 配置范围 | 全局一份（押金/时长等），总账号可改；**通行范围是购卡时选中的门店**，不是全店通用 |
| 出店判定 | **出店闸机**刷脸成功视为离店（进店闸机只负责进店计时，不靠同机二次刷脸） |
| 按时离店后退款 | 全额退，参观权结束，撤销该店因参观而下发的闸机权限（若仍有会员则保留会员权限） |
| 超时 | 到点未从出店闸机离开 → 扣押金；仍可在宽限内从出店闸机离开以结束行程 |
| 与正式会员 | **选中门店已有未过期会员（含跨店会员）则不可再买该店参观卡**；会员进店仍走会员逻辑 |
| 管理端 | 总账号：配置页 + 参观记录；门店账号：可看本店参观记录（只读） |

---

## 3. 离店怎么判定（重要说明）

每店配置两台闸机：**进店闸机**（门口）、**出店闸机**（出口）。厂商仍只有验脸开门与通行记录，没有单独「出店 HTTP」；系统靠**设备方向**区分：

1. **进店闸机**刷脸成功 → 记进店，开始计时（`UNUSED → IN_STORE`）。
2. **出店闸机**刷脸成功 → 记离店：未超时则退押金，已超时扣款则只结束行程。
3. 进店闸机连刷只防抖，**不会**误判为离店。
4. 小程序提示：「请从进店闸机入场，从出店闸机离场」。

局限：若不刷出店闸机离开（如消防通道），系统无法感知，靠**超时自动扣押金**兜底。

在线人数：窗口内每人最后一次成功刷脸若在进店闸机则算在店，在出店闸机则不算。

## 4. 管理端配置项

| 配置 | 说明 | 默认建议 |
| --- | --- | --- |
| 是否开启 | 关则小程序不展示购买入口 | 关 |
| 押金（分） | 支付金额 | 990（¥9.90） |
| 可参观时长（分钟） | 从进店成功起算 | 60 |
| 有效期（天） | 从支付成功起算 | 30 |
| 提醒提前量（分钟） | 首页强调提醒 | 5 |
| 说明文案 | 购卡页展示 | 内置默认文案（写明仅限选中门店、进出闸机） |

---

## 5. 小程序表现

首页：参观中置顶倒计时；未进店显示**门店名 + 有效期 + 退款**；开启且当前店可买时显示「到店参观」入口。

购卡页写明：押金、**仅当前选中门店**、进店/出店闸机、按时退、超时扣、未进店可退。

---

## 6. 状态机（摘要）

```
支付成功 → UNUSED（已绑定下单门店 store_id）
  ├─ 未进店主动退 / 到期自动退
  └─ 进店闸机刷脸 → IN_STORE
        ├─ 出店闸机刷脸且未超时 → 退押金结束
        ├─ 超过 due_exit_at → TIMEOUT_FORFEIT
        └─ 出店闸机刷脸（已超时）→ 结束行程不退款
```

## 7. 本期已实现范围

- 库表 `visit_pass`（含购卡即写入的 `store_id`）+ 配置项
- 闸机 `gate_device.direction` / `door_log.direction`（ENTRY/EXIT）
- 管理端参观配置、闸机进出方向、通行记录
- 小程序首页状态/入口、购卡页、未进店退款、倒计时
- 闸机：仅绑定门店可开；进店闸机计时；出店闸机离店并退款；超时扣款任务

# 发布：闸机

← 返回 [发布文档](发布文档.md)

设计细节见 [闸机对接开发设计](闸机对接开发设计.md)；需求背景见 [需求/闸机对接](../需求/闸机对接.md)。

域名与证书必须先按 [域名与 Nginx](发布-域名与Nginx.md) 配好，闸机才能连上正式环境。

---

## 需要配置什么

闸机屏只连 **HTTPS API + WSS**，设备序列号在**管理后台**维护，不写进 Nginx。

| 项 | 说明 | 谁配 |
| --- | --- | --- |
| `https://api.example.com` | 业务 API（与小程序同一域名） | Nginx + Java 已上线 |
| `wss://api.example.com/ws/gate` | 长连接；路径固定 `/ws/gate` | Nginx 反代须带 WebSocket 头（配置里已写好） |
| 设备 SN | 与闸机出厂/屏端配置一致 | 管理端「闸机」菜单新增 |

`wss://` = WebSocket over TLS，和 `https://` 共用证书。屏上不要填 `ws://`（非加密），正式环境会失败或被拒。

本地联调才用：`ws://127.0.0.1:8080/ws/gate`（电脑与闸机要在同一可达网络；`127.0.0.1` 闸机访问不到你的笔记本）。

## 上线检查清单（按顺序）

1. 浏览器能打开 `https://api.example.com/api/health`。  
2. Nginx 的 `api` 站点里已有 `Upgrade` / `Connection` 相关配置（见 [域名与Nginx §配置](发布-域名与Nginx.md#6-写-nginx-配置详细可抄)）。  
3. 管理端 `https://admin.example.com` 能登录。  
4. 管理端 → 闸机：新增设备，填 SN、名称、所属门店；需要时可编辑、删除。  
5. 闸机屏/厂商配置里填写：  
   - API 基址：`https://api.example.com`  
   - WebSocket：`wss://api.example.com/ws/gate`  
   - SN：与后台完全一致  
6. 购卡并采集正脸后，看闸机是否收到下发、认脸能否开门（细节见开发设计）。

连不上时优先查：DNS、证书是否过期、安全组 443、Java 是否 `active`、SN 是否一致、是否误写成 `ws://` 或错路径。

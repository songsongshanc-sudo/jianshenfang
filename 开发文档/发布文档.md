# 发布文档

线上发布前要配齐的密钥、域名和闸机。本地怎么跑、哪些功能是测试数据，见 `开发文档/调试文档.md`。去哪些平台申请，见 `开发文档/上线申请清单.md`。

进程的 `SPRING_PROFILES_ACTIVE` 必须是 `prod`。密钥写在服务器环境变量里，不进 Git。`prod` 缺配置时接口会直接拒绝，不会走本地那套测试数据。

下面「代码是否已读取」一列：已读取表示变量写上就会生效；未读取表示名字先留在这里，代码接上之前，即使写了环境变量，`prod` 仍会拒绝。

## 二、微信

这些值不在微信开发者工具里填写。小程序按企业或个体工商户注册并完成认证。个人主体不能使用手机号快速验证，也不能按小程序支付接入。

`AppSecret`、APIv3 密钥和私钥文件只放在跑后端的服务器上。当前代码还没读取这些变量，值齐了还要再接微信接口。

### 小程序 AppID 和 AppSecret

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，账号类型选小程序。注册说明见[小程序起步](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/getstart.html)。
2. 管理员微信扫码登录。左侧「管理 → 开发管理 → 开发设置」。
3. AppID 记为 `WX_MP_APPID`。AppSecret 点「生成」，只显示一次，记为 `WX_MP_SECRET`。查看和重置见[官方文档](https://developers.weixin.qq.com/doc/oplatform/developers/dev/appid)。
4. 同一个 AppID 填进 `code/mp/src/manifest.json` 的 `mp-weixin.appid`。
5. 小程序访问后端的域名，填在同一页的「服务器域名」。request、uploadFile、downloadFile 都要包含后端的 HTTPS 域名。WebSocket 域名填闸机长连接用的域名。

手机号快速验证说明见[手机号快速验证组件](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber)。每次调用成功约 0.03 元，每个小程序有 1000 次体验额度。

### 微信支付

1. 打开 [微信支付商户平台](https://pay.weixin.qq.com/) 点「成为商家」。材料见[小程序接入指引](https://pay.weixin.qq.com/static/applyment_guide/applyment_detail_miniapp.shtml)。
2. 主体选个体工商户或企业。通过后的商户号记为 `WX_PAY_MCH_ID`。
3. 「产品中心 → APPID授权管理 → 关联 AppID」，绑上小程序 AppID。步骤见[绑定 AppID](https://pay.weixin.qq.com/doc/v3/merchant/4016328613)。
4. 「账户中心 → 账户设置 → API安全 → 设置 APIv3 密钥」，32 位数字和大小写字母，记为 `WX_PAY_API_V3_KEY`。设置后不能再查看。说明见[配置 APIv3 密钥](https://pay.weixin.qq.com/doc/v3/merchant/4012072195)。
5. 同一页申请「商户API证书」。`apiclient_key.pem` 放到服务器，路径记为 `WX_PAY_PRIVATE_KEY_PATH`。证书序列号记为 `WX_PAY_MCH_SERIAL`。说明见[申请商户 API 证书](https://pay.weixin.qq.com/doc/v3/merchant/4012072428)。
6. `WX_PAY_NOTIFY_URL` 由我们自己定，必须是外网 HTTPS。下单时服务器把这个地址告诉微信。

全部门店是否共用一个商户号还没定。门店上的商户号字段仍为空，先按一个商户号准备。

## 三、高德地图

Key 不配在后端。写在 `code/admin/.env.local`，这个文件进 Git。`npm run dev` 和 `npm run build` 都会读它：

```
VITE_AMAP_KEY=高德 Web端(JS API) Key
VITE_AMAP_SECURITY_JS_CODE=高德安全密钥
```

在 `code/admin` 执行 `npm run build`，把 `dist` 部署到管理端网站。已经打好的包不会再读服务器环境变量，改 Key 后要重新打包。高德控制台把正式管理端域名加到这把 Key 的域名白名单。安全密钥会出现在浏览器里，这是高德 JS 地图的用法。

`npm run dev` 不会读 `.env.production.local`。只有正式环境要换另一把 Key 时，才在打包机器上写 `.env.production.local`，它只在 `npm run build` 时盖过 `.env.local`。

`application.yml` 里的 `TENCENT_MAP_KEY` 是旧的腾讯逆地理变量，当前选点不读取它。

## 四、闸机上要配置的

闸机主动连我们的服务器。管理端登记设备号，闸机连上后用机身设备号对上。协议见 `需求/闸机对接.md`。

### 管理端

1. 总账号新增闸机，设备号填机身屏幕上的编号，指定所属门店，状态启用。
2. 号对不上时，开门接口返回未知设备，人脸也不会下发。
3. 需要签名时，总账号在这台设备上生成口令。口令存在设备记录里，不进 Git。生成后要下发到闸机，只显示一次。

### 闸机屏幕

长按主页进入设置，默认密码 `123456`。

1. 公共设置里，设备对接方式选「开发者」。
2. 服务器填已备案域名和端口，通讯选 HTTPS。设置页预览出的地址应带 `/api/v1/verify_user`，闸机认完脸用它问能不能开门。
3. 长连接选 WebSocket，地址填 `wss://域名:端口/ws/gate`。子路径必须是 `/ws/gate`，留空连不上。
4. 识别设置里打开「识别后在线验证」。可通行人员选「已注册用户」。选「任何人」时，记录会全部进陌生人接口，门仍然按验证结果决定开不开。
5. 若总账号启用了签名口令，把同一套口令配进闸机。未启用时服务端不校验签名。

连上后闸机会发 `declare`。服务端按设备号找到已登记的那一台，回复心跳、对时、把识别间隔设为 15 秒，并关闭「验证失败仍放行」。购卡后的人脸从这时开始下发。

没买会员的人脸不会下发。闸机认不出的人记一条未开门，管理端显示「陌生人」，在线人数不算这些人。

## 五、规则已定、上线后仍按此执行

1. 人脸只收一张正脸，不能从相册选。服务端只检查照片大小。购卡后下发到本店闸机，由闸机认脸。
2. 图片用对象存储。厂商选定前，`prod` 不能上传。
3. 课时码不能开闸机。
4. 好评赠卡、学生认证、美团和抖音自动核销还没做，上线后这些入口不会发会员、不会改价格。团购仍由总账号在管理端录入券码。

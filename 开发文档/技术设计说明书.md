# 24 小时自助健身房 — 技术设计说明书

配套需求：`需求/24小时自助健身房小程序需求说明书.md`（后补拍板在该文第 11 节）。闸机屏怎么填见 `开发文档/闸机屏端配置.md`。新机器怎么装见 `开发文档/正式服务器配置.md`。测试云怎么操作见 `开发文档/调试文档.md`。

本文描述**当前代码**，不保留已经废弃的方案。

| 项 | 内容 |
| --- | --- |
| 后端 | Java 17，Spring Boot 3.5.5，单体 |
| 小程序 | uni-app（Vue 3），只发微信 |
| 管理端 | Vue 3 + Element Plus + ECharts |
| 数据 | 正式环境 MySQL 8 + Redis。表结构用 Flyway，当前到 `V20` |
| 文件 | 公开图在云服务器 `/var/lib/gym/public`，经 `/uploads/` 访问。人脸在应用工作目录 `data/private/face`。器械视频走微信视频号，不存视频文件 |
| 支付 | 微信支付 APIv3。正式环境 `gym.pay.mock-enabled=false` |
| 时区 | `Asia/Shanghai` |

---

## 1. 边界

1. 小程序、管理端、闸机只访问这一个后端。
2. 支付密钥、会员是否有效、人脸是否入库，只在服务端判断。
3. 进店只做人脸。小程序没有开门码。课时二维码只扣课，不能开闸机。
4. 不买人脸云，不买对象存储。闸机自己认脸；服务端用 WebSocket `/ws/gate` 下发人员，用 HTTP 回答能不能开门。
5. 管理端分总账号和门店账号。总账号看全部门店，门店账号只看绑定的那一家。
6. 会员卡、课时买完不能退款、不能停卡、不能改门店。参观押金是例外，见需求第 11 节。
7. 会改闸机里人员的管理端操作，闸机不在线就整笔失败，数据库一起回滚。避免服务端和闸机各记各的。

## 2. 架构

```
微信小程序                    PC 管理端（静态文件）
        \                         /
         Nginx（正式环境 HTTPS）
                    |
            Spring Boot  /opt/gym/gym-server.jar
            只监听 127.0.0.1:8080
              |            |
           MySQL 8       Redis（登录令牌）
              |
        公开图 /var/lib/gym/public
        人脸   /opt/gym/data/private/face

闸机 --WebSocket /ws/gate--> 下发 addUser / editUser / delUser
闸机 --HTTP 在线验证--------> 问现在能不能开门
```

一个仓库，三个工程：`code/server`、`code/admin`、`code/mp`。不拆微服务。

根包 `com.gym.self`。业务在 `modules` 下，按功能分包，不按早期设计里的 `trade` / `entry` / `coach` 空目录。

| 包 | 做什么 |
| --- | --- |
| `user` | 小程序登录、人脸、会员编号、管理端会员、进门管理员 |
| `adminuser` | 总账号 / 门店账号登录、操作日志、清空数据暗门 |
| `store` | 门店、电话、到店指引 |
| `content` | Banner、公告、协议、服务说明、系统配置 |
| `card` | 卡种、会员资格、剩余天数 |
| `order` | 下单、支付、后台开卡开课 |
| `gate` | 设备、WebSocket、人脸下发、开门判定、通行记录 |
| `visit` | 参观押金 |
| `shop` | 教练、课包、团购券、报修投诉失物、加盟 |
| `lesson` | 约课、选座、申诉、课时码 |
| `report` | 财务报表 |
| `file` | 公开图片 |
| `geo` | 管理端选点用的坐标 |

金额用「分」的整数。雪花 ID 对前端用字符串。

## 3. 登录与会员

小程序打开时用 `jscode2session` 认出微信。已绑定的微信直接进首页。

还没绑定的，登录页两条路：

- 勾选隐私指引后，「使用本机号登录」才拉起微信手机号组件。隐私指引是管理端配置的 http(s) 链接，不是《会员协议》。
- 「其他号码登录」走短信。阿里云短信还没接，发送接口直接返回「短信尚未配置」。

人脸只在信息完善时用相机拍一张，不从相册选。正式环境把照片交给在线闸机做 `verifyPhoto`。失败可重拍。拍脸成功还不发会员编号。提交姓名后才写成正式会员并发号。

已是正式会员的手机号：登录只绑定当前微信，不改姓名、不重拍。该手机号已绑别的微信则拒绝。退出登录会清掉微信绑定。

小程序里不能改姓名、手机号、人脸。管理端可以改姓名和手机号，可以解绑微信，不能改人脸。

管理端录入会员：姓名、手机号、人脸必填，卡和课程可选。建档当时就是正式会员。每张卡、每门课各记一笔已支付订单，金额按标价，进入财务报表。

会员列表只列出有手机号或会员编号、且不是教练、也不是进门管理员的人。状态有在线、停用、未完成注册。停用不是物理删除：闸机删掉这个人，恢复后再按下发。闸机不在线则停用、恢复、改卡都失败。

编辑会员在浏览器里先改，点保存后列出变更，确认后一次写入。没改动就直接关掉。删卡会把后面叠上去的天数往前挪，闸机到期日跟着变，并把这张卡对应的已支付订单改成作废，报表不再计入。删课程同样把该课包仍为已支付的订单作废。

旧闸机人员可以按在线设备导入。编号以 `DL` 开头、黑名单、没有照片的跳过。

## 4. 卡、订单、报表

买卡、买课、参观都走 `trade_order`。支付成功才履约。同一卡种再买，新的一段接在该卡当前结束时间之后，不从付款当天重算。

未过期再买同一张卡、或课包还有剩余课时再买同一个课包，若后台配了大于 0 的提前续约价，按这个价付一笔。没有自动扣款。

管理端报表只加总状态为 `PAID` 的订单。删除会员卡或课程后订单变为 `VOID`，金额从报表去掉。订单列表显示「已作废」。这不是微信退款。

财务报表在管理端工作台，可按时间、门店看卡种、课程、门店，并导出 xlsx。

## 5. 闸机

厂商协议说明在 `需求/闸机对接.md`。屏上填的域名和端口以 `开发文档/闸机屏端配置.md` 为准。

已接的方向：

| 方向 | 作用 |
| --- | --- |
| 闸机 → `POST /api/v1/verify_user` | 认出会员编号后问能不能开门 |
| 闸机 → 通行记录、陌生人记录 | 只记账，必须回成功 |
| 服务端 → `addUser` / `editUser` / `delUser` | 下发或删除人员和到期时间 `id_valid` |
| 闸机连上 `/ws/gate` | 报设备号，服务端校时并关闭「验证失败也放行」 |

`user_id` 用会员编号。在线验证决定开不开门；`id_valid` 是断网时闸机自己留的到期时间。

能开门的人：本店未过期会员、符合规则的参观、以及到了期日之前的教练和进门管理员。教练、进门管理员不出现在会员列表里。

设备有进店、出店两个方向，用来判断参观是否离店。管理端「在线」指最近约 3 分钟内有心跳且 WebSocket 还连着。

## 6. 教练、进门管理员、约课

教练用手机号在小程序登录，档案在 `coach` 表。编辑教练可以填闸机到期时间。已有人脸且本店闸机在线时，保存会下发；没有人脸则只记下时间，等人脸入库后再下发。

总账号右上角「账号管理」：改总账号密码；维护进门管理员（姓名、手机号、人脸、闸机到期）。可以多名。他们刷脸进所在门店，支持编辑和删除。左侧菜单里的「账号管理」仍是门店登录账号。

约课：学员在已购课包上选日期、开始时间和座位。提交先锁座不扣课，教练同意后扣 1 节。未同意可取消。已同意且距开课不足 24 小时不能取消。可申诉，教练退课加回 1 节。不预约时仍可用课时二维码，由教练核销。关键节点写入站内消息，管理端可按门店、教练查看。

续课率：同一学员把某教练的一包课上完后，再买这个教练的任意课包，算续上。课时还没用完就又买，算提前续约，不算续课成功。

---

## 7. 参观

全局一份配置（是否开启、押金、可参观分钟、有效天数）。购买时绑定当前门店。本店已有未过期会员不能再买该店参观卡。

进店闸机刷脸开始计时，出店闸机刷脸且未超时则全额退押金。超时扣掉押金。买了没进店可以自己退，到期也会自动退。正式会员卡没有这条退款通路。

## 8. 配置与密钥

正式环境 `SPRING_PROFILES_ACTIVE=prod`。密钥只在服务器 `/etc/gym/gym-server.env`，不写进 Git。

| 变量 | 作用 |
| --- | --- |
| `MYSQL_*` / `REDIS_*` | 数据库和登录态 |
| `JWT_ADMIN_SECRET` / `JWT_MP_SECRET` | 两套令牌，上线必须换成随机串 |
| `WX_MP_APPID` / `WX_MP_SECRET` | 小程序登录。AppSecret 只在服务器，32 位 |
| `WX_PAY_*` | 商户号、APIv3 密钥、私钥文件路径、序列号、回调 `https://api.域名/api/mp/pay/notify` |
| `PUBLIC_FILE_DIR` | `/var/lib/gym/public` |
| `PUBLIC_FILE_BASE_URL` | 公开图使用的网址，正式环境用 `https://api.域名` |

小程序接口地址在 `code/mp/src/api/http.ts` 和 `auth.ts`，两处要一致。微信 AppID 填 `manifest.json` 的 `mp-weixin.appid`。管理端请求用相对路径 `/api`，由 Nginx 转发，不用改地址。管理端地图 Key 是构建时的 `VITE_AMAP_KEY`、`VITE_AMAP_SECURITY_JS_CODE`，不进后端 env。

进程：`/etc/systemd/system/gym-server.service`，工作目录 `/opt/gym`，jar 为 `/opt/gym/gym-server.jar`。

## 9. 上线前要删的调试入口

管理端右上角「总账号」按住约 0.8 秒，会确认后调用 `POST /api/admin/system/wipe`：清空业务数据，并向在线闸机删除人员。总账号密码保留。闸机不在线且库里还有人时，整次失败，库不先删。

正式上线前删掉这一入口。位置：

- `code/admin/src/layouts/AdminLayout.vue` 里按住「总账号」的计时和确认框
- `DataWipeController`、`DataWipeService`
- `GateFaceSync.removeEveryone`

## 10. 明确不做

- 开门码、人脸云、对象存储、会员卡原路退款、停卡、改门店
- 小程序里改姓名、手机号、人脸
- 短信营销；登录短信通道尚未接入
- 好评赠卡、学生认证折扣、美团/抖音自动核销（团购是管理端录入券码）
- 微信支付委托代扣、自动续费

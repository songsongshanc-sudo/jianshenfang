# 调试文档

两套用法分开。本机调试连自己电脑上的后端。线上是测试云 `http://59.110.11.215`，profile 是 `prod`。公司以后的正式云另装，不要把这台数据库迁过去。

登录、启停、换包的命令见 [服务器常用命令](服务器常用命令.md)。域名和证书见 [现在能做与域名下来再做](现在能做与域名下来再做.md)。

PowerShell 一条一条执行，不要用 `&&`。

---

## 1. 本地和线上各改哪里

日常调试不要改接口地址。下表里写「不改」的，保持仓库现状即可。

| 要做的事 | 改哪里 | 怎么处理 |
| --- | --- | --- |
| 本机管理端 | 不用改 | `code/admin` 里 `npm run dev`。`vite.config.ts` 只在这个命令下把 `/api` 转到 `http://127.0.0.1:8080` |
| 本机小程序（开发者工具） | 不用改 | `code/mp/src/api/http.ts` 和 `auth.ts` 里，非 H5 仍是 `http://127.0.0.1:8080`。这里的 `127.0.0.1` 是运行小程序的那台电脑 |
| 本机后端 | 不用改 yml | 启动时加上 profile `local`。短信码、模拟支付、测试人脸只在这个 profile 里 |
| 浏览器打开线上管理端 | 不用改源码 | 打包后的 `baseURL` 是 `/`，请求发给当前网址。改了页面要重新 `npm run build` 再上传 |
| 别人用浏览器看小程序 | 不用改上面两行微信地址 | H5 编译会自动改成「当前网址」。执行 `npm run build:h5` 后上传。测试云的 env 要有 `MP_H5_LOGIN=true` |
| 真机微信小程序 | 等域名和备案 | 到那时把非 H5 的地址改成 `https://api.xz100w.com`。现在改成公网 IP，手机仍然打不开 |

不要做这些：

- 不要把小程序地址改成 `http://59.110.11.215` 来做日常调试。线上是 `prod`，验证码 `246810`、模拟支付、测试人脸都不会生效。
- 不要在 `code\admin` 里执行 Maven。Maven 只用于 `code\server`。
- 不要为了连线上去改 `vite.config.ts`。那个代理只有 `npm run dev` 才用。打开 `http://59.110.11.215` 时不经过它。
- 公司正式服务器不要写 `MP_H5_LOGIN=true`。

## 2. 本机怎么跑

三个窗口。8080 上只能有一个后端。先起后端，再开管理端和开发者工具。

### 后端

工作目录必须是 `code\server`。数据在这个目录的 `data` 里。本机没有 `mvn` 命令时，用仓库里的 Maven。

```powershell
cd D:\AIProject\健身房小程序\code\server
D:\AIProject\健身房小程序\.tools\apache-maven-3.9.9\bin\mvn.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```

看到 `Started GymApplication` 后，另开一个窗口：

```powershell
curl.exe -sS http://127.0.0.1:8080/api/health
```

应返回 `{"code":0,"message":"ok",...}`。这个地址只在这台电脑上有效。关掉这个窗口，后端就停了。

`local` 用 H2，不连 MySQL、Redis。登录态在内存里，重启后端后管理端和小程序都要重新登录。总账号 `admin` / `admin123`。

Flyway 报校验失败时，停掉后端，删掉 `code\server\data` 里的 H2 文件再启动。库会按空库重建，本机录入的会员和门店会丢掉。

### 管理端

```powershell
cd D:\AIProject\健身房小程序\code\admin
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`。页面改完会自己刷新，不用重新打包。

### 小程序

```powershell
cd D:\AIProject\健身房小程序\code\mp
npm install
npm run dev:mp-weixin
```

微信开发者工具导入 `code\mp\dist\dev\mp-weixin`。打开「详情 → 本地设置」，勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。`manifest.json` 的 appid 是空的，导入时可选测试号。

`dev:mp-weixin` 会一直占着窗口。改了源码，开发者工具里重新编译即可。若用的是 `npm run build:mp-weixin`，产物在 `code\mp\dist\build\mp-weixin`，每次改完要重新执行这条再编译。

本机不要用 `npm run dev:h5` 对后端。H5 的接口是当前网址，开发服务没有把 `/api` 转到 8080，页面会请求失败。本机看小程序用上面的开发者工具。

### 本机能用的测试能力

这些只在 profile 为 `local`、并且小程序不是微信正式版时成立。线上 `prod` 没有。

| 功能 | 本机 |
| --- | --- |
| 注册验证码 | 登录页预填 `246810`。服务端只在 `local` 且 `gym.sms.fixed-code` 正好是这个值时接受。先点获取验证码，再提交 |
| 人脸 | 非正式版可以不拍真人，上传测试照片。文件在 `code\server\data\private\face` |
| 支付 | 点「模拟支付成功」。不是微信支付 |
| 微信登录 | 不调微信。开发者工具里的 code 在本机换成测试 openid |
| 图片 | 写到 `code\server\data\public`，地址是 `http://127.0.0.1:8080/uploads/...`。本机浏览器打得开 |
| 内容安全 | 文字里包含「违禁」会拒绝。不调微信 |
| 团购 | 管理端先录入券码。不调美团、抖音 |
| 绑定码 | 管理端录入会员或教练后，小程序用「绑定码登录」。不用注册、不用验证码 |

教练登录：管理端教练列表里的手机号和绑定码，与小程序「绑定码登录」一致。

## 3. 线上测试云怎么用

不要在本机再开一个 8080 给别人访问。别人打开的是云服务器。服务器上的 Java 由 systemd 管着，关掉本机 PowerShell 不影响它。

| 谁用 | 地址 |
| --- | --- |
| 管理端 | `http://59.110.11.215` |
| 小程序 H5 | `http://59.110.11.215/h5/` |
| 接口自测 | `http://59.110.11.215/api/health` |

手机系统浏览器要保留开头的 `http://`。微信里打开公网 IP 经常失败。域名和证书好了再改成 `https://admin.xz100w.com` 和 `https://api.xz100w.com`。

线上是 `prod`：

- 注册会提示短信还没配置。给别人试用时，在管理端录入会员或教练，让对方用绑定码登录。
- 没有「模拟支付成功」，也没有测试人脸。
- 管理端上传图片后，地址应是 `http://59.110.11.215/api/uploads/...`。若仍是 `127.0.0.1`，说明服务器还在跑旧 jar，按下面第 4 节换成新包。
- H5 能登录，是因为这台机器的 `/etc/gym/gym-server.env` 里有 `MP_H5_LOGIN=true`。改完这项要 `sudo systemctl restart gym-server`。

开发者工具仍然连本机第 2 节，不要改去连这台云。这样验证码和模拟支付还能用。

## 4. 改完代码怎么放到线上

只上传改过的那一端。

后端。本机打包再上传，然后在服务器上重启：

```powershell
cd D:\AIProject\健身房小程序\code\server
D:\AIProject\健身房小程序\.tools\apache-maven-3.9.9\bin\mvn.cmd -DskipTests package
scp "D:\AIProject\健身房小程序\code\server\target\gym-server-0.1.0.jar" root@59.110.11.215:/opt/gym/gym-server.jar
```

```bash
sudo systemctl restart gym-server
```

`scp` 到 `100%` 就是传完了。重启后等十几秒再访问。`curl` 若提示连接被拒绝，再等一会儿。

管理端。只影响 `http://59.110.11.215`，不用重启 Java：

```powershell
cd D:\AIProject\健身房小程序\code\admin
npm run build
scp -r "D:\AIProject\健身房小程序\code\admin\dist\*" root@59.110.11.215:/tmp/gym-admin-dist/
```

```bash
sudo mkdir -p /var/www/gym-admin
sudo rm -rf /var/www/gym-admin/*
sudo cp -r /tmp/gym-admin-dist/* /var/www/gym-admin/
```

H5。只影响 `http://59.110.11.215/h5/`：

```powershell
cd D:\AIProject\健身房小程序\code\mp
npm run build:h5
scp -r "D:\AIProject\健身房小程序\code\mp\dist\build\h5\*" root@59.110.11.215:/tmp/gym-h5/
```

```bash
sudo mkdir -p /var/www/gym-h5
sudo rm -rf /var/www/gym-h5/*
sudo cp -r /tmp/gym-h5/* /var/www/gym-h5/
```

清空线上会员、订单和图片的命令在 [服务器常用命令](服务器常用命令.md)。那一段只给这台测试云用。

## 5. 另一台电脑用 Docker（`dev`）

管理端和小程序与第 2 节相同。后端改成：

```powershell
cd D:\AIProject\健身房小程序\code
docker compose up -d
cd D:\AIProject\健身房小程序\code\server
D:\AIProject\健身房小程序\.tools\apache-maven-3.9.9\bin\mvn.cmd spring-boot:run
```

不加 `profiles=local` 时，默认 profile 是 `dev`。MySQL 库 `gym`，用户 `gym`，密码 `gym_dev`。Redis 无密码。登录态在 Redis 里，重启后端不用重新登录。

`dev` 有模拟支付，没有 `246810`。验证码只在第 2 节的 `local` 里。本机 `code\server\data` 的 H2 数据不会进这个 MySQL。

这台电脑装不了 Docker 时，用第 2 节。

## 6. 换电脑时不要拷的目录

| 目录 | 原因 |
| --- | --- |
| `code/admin/node_modules`、`code/mp/node_modules` | 新电脑各自 `npm install` |
| `code/server/target` | Maven 编译结果 |
| `code/mp/dist`、`code/admin/dist` | 到新电脑后重新编译 |
| `.tools` | 本机临时 Maven |
| `code/server/data` | 只属于 `local` 的 H2 和上传文件。要接着用旧数据时单独拷，拷的时候后端必须停着 |

版本：JDK 17、Maven 3.9.9、Node.js 22。

端口：`8080` 后端，`5173` 本机管理端，`3306` MySQL，`6379` Redis。线上不要把 3306、6379、8080 放进安全组。

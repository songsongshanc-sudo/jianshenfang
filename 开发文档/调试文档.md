# 调试文档

只写测试云 `59.110.11.215` 上的操作。新的一台正式服务器按 [正式服务器配置](正式服务器配置.md) 从头装，不要把这台库迁过去。闸机屏上填什么见 [闸机屏端配置](闸机屏端配置.md)。

PowerShell 一条一条执行，不要用 `&&`。

先分清在哪执行：

- **本机 PowerShell**：`ssh`、`scp`、`mvn`、`npm`。
- **服务器**：登录进去之后的 `systemctl`、`mysql`、`nginx`。关掉本机窗口不会关掉服务器上的服务。

Maven 只在 `code\server` 里执行。本机没有 `mvn` 命令时用仓库里的：

`D:\AIProject\健身房小程序\.tools\apache-maven-3.9.9\bin\mvn.cmd`

## 1. 这台机器现在是什么

profile 是 `prod`。Java 只听本机 8080，外网走 Nginx 的 80 端口。

| 地址 | 实际内容 |
| --- | --- |
| `http://59.110.11.215/` | 管理端，文件在 `/var/www/gym-admin` |
| `http://59.110.11.215/h5/` | 小程序 H5，文件在 `/var/www/gym-h5`。浏览器里不能微信登录 |
| `http://59.110.11.215/api/` | 转到 `127.0.0.1:8080` |
| 公开图 | `/var/lib/gym/public`，经 `/uploads/` 访问 |
| 人脸 | `/opt/gym/data/private/face` |
| 程序 | `/opt/gym/gym-server.jar` |
| 配置 | `/etc/gym/gym-server.env` |
| Nginx | `/etc/nginx/conf.d/gym.conf` |

小程序源码里非 H5 的接口地址是 `http://59.110.11.215`（`http.ts` 和 `auth.ts` 两处相同，不要加 `:8080`）。微信开发者工具要勾选「不校验合法域名」才能用这个 IP。手机预览仍会校验合法域名，真机打不开这个地址。正式域名下来后再改成 `https://api.你的域名`。

管理端打包后的接口是相对路径 `/`，打开 `http://59.110.11.215` 即可，不用改源码里的地址。

## 3. 看后端是否正常

```bash
sudo systemctl status gym-server
curl -sS http://127.0.0.1:8080/api/health
curl -sS http://59.110.11.215/api/health
```

`status` 应是 `active (running)`。两条 `curl` 都应是 `{"code":0,"message":"ok",...}`。刚启动要等几秒再 curl。

```bash
sudo systemctl start gym-server
sudo systemctl restart gym-server
sudo systemctl stop gym-server
```

日志：

```bash
sudo journalctl -u gym-server -n 100 --no-pager
sudo journalctl -u gym-server -f
sudo journalctl -u gym-server --since "10 min ago" --no-pager
```

`journalctl -f` 用 `Ctrl+C` 停下，服务还在跑。

按词过滤：

```bash
sudo journalctl -u gym-server --since "10 min ago" --no-pager | grep -E "闸机|declare|verifyPhoto|jscode2session"
sudo journalctl -u gym-server --since "10 min ago" --no-pager | grep -A 40 "未处理异常"
```

堆栈里 `Caused by:` 后面那一句是真正的报错。

## 6. 改配置

编辑后必须重启后端。不要把文件内容贴到聊天里。

```bash
sudo nano /etc/gym/gym-server.env
sudo chmod 600 /etc/gym/gym-server.env
sudo systemctl restart gym-server
```

只看变量名、不看值：

```bash
sudo grep -E '^[A-Z_]+=' /etc/gym/gym-server.env | cut -d= -f1
```

微信登录失败且日志是 `40125`：`WX_MP_SECRET` 不对。AppSecret 是 32 位，多贴了一遍要改回前 32 位再重启。

Nginx：

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl status nginx
```

`nginx -t` 必须先成功再 reload。reload 不会断 SSH。

## 7. MySQL 和 Redis

3306、6379 不要对公网开放。

```bash
sudo systemctl status mysql
sudo systemctl restart mysql
mysql -u gym -p -h 127.0.0.1 gym
```

进去后 `SHOW TABLES;`，离开用 `EXIT;`。

Redis 只存登录态。`FLUSHALL` 会让所有人重新登录，不清会员。

```bash
sudo systemctl status redis-server
redis-cli ping
redis-cli FLUSHALL
```

`PONG` 表示 Redis 在跑。

## 8. 磁盘和端口

```bash
df -h
free -h
sudo du -sh /var/lib/gym/public /opt/gym /opt/gym/data/private
sudo ss -lntp | grep -E ':22|:80|:443|:8080|:3306|:6379'
```

8080、3306、6379 应只出现在 `127.0.0.1`。

开机自启确认：

```bash
sudo systemctl is-enabled gym-server mysql redis-server nginx
```

四行都应是 `enabled`。`sudo reboot` 会断开 SSH，过一两分钟再登录，然后看 `systemctl status gym-server`。

## 9. 清空这台测试云的业务数据

会删掉会员、订单、门店、教练、图片和人脸。数据库账号、环境变量、jar、Nginx 还在。Flyway 会按空库重建表，总账号回到 `admin` / `admin123`。**正式服务器不要执行。**

```bash
sudo systemctl stop gym-server
sudo mysql <<'EOF'
DROP DATABASE IF EXISTS gym;
CREATE DATABASE gym DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
GRANT ALL PRIVILEGES ON gym.* TO 'gym'@'localhost';
FLUSH PRIVILEGES;
EOF
sudo rm -rf /var/lib/gym/public/*
sudo mkdir -p /var/lib/gym/public
sudo rm -rf /opt/gym/data/private
redis-cli FLUSHALL
sudo systemctl start gym-server
curl -sS http://127.0.0.1:8080/api/health
```

`curl` 被拒绝就等十几秒再执行。启动失败看 `sudo journalctl -u gym-server -n 100 --no-pager`。

这条命令清的是数据库和磁盘，清不掉闸机里已经下发的人脸。要连闸机一起清，用管理端暗门：右上角「总账号」按住约 0.8 秒。闸机不在线时暗门会失败，库不会先删。这个暗门正式上线前必须删掉，见 [正式服务器配置](正式服务器配置.md) 最后一节。

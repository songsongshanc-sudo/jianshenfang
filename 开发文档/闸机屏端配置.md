# 闸机屏端配置

闸机屏端分两处填：**HTTP** 和 **WebSocket（WS）**。下面给「纯 IP 调试」和「正式域名」两套配置，其余字段两种场景相同。

> 测试云操作见 [调试文档](调试文档.md)。新服务器和正式域名见 [正式服务器配置](正式服务器配置.md)。

## 一、字段说明

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| HTTP | 域名/IP | 业务接口所在服务器 |
| HTTP | 端口 | 后端 HTTP 端口 |
| WS | WebSocket 服务器（域名/IP） | 长连接所在服务器 |
| WS | 子路径 | **固定 `/ws/gate`** |
| WS | 端口 | 长连接端口 |

## 二、纯 IP 配置（调试阶段，http/ws）

| 分组 | 字段 | 值 |
| --- | --- | --- |
| HTTP | 域名/IP | `59.110.11.215` |
| HTTP | 端口 | `8080` |
| WS | WebSocket 服务器 | `59.110.11.215` |
| WS | 子路径 | `/ws/gate` |
| WS | 端口 | `8080` |

> 仅当闸机固件**不强制 TLS** 时可用。若闸机只认 https/wss（屏上填 `ws://` 会被拒），则必须按下面「正式域名」先配好证书和 Nginx。

## 三、正式域名配置（https/wss）

| 分组 | 字段 | 值（示例） |
| --- | --- | --- |
| HTTP | 域名/IP | `api.example.com` |
| HTTP | 端口 | `443` |
| WS | WebSocket 服务器 | `api.example.com` |
| WS | 子路径 | `/ws/gate` |
| WS | 端口 | `443` |

> 域名、证书、Nginx 反代（含 WebSocket 的 `Upgrade`/`Connection` 头）见 [正式服务器配置](正式服务器配置.md)。

## 四、两种场景都一样的字段

| 字段 | 值 |
| --- | --- |
| 对接方式 | 开发者 |
| 设备 SN | 闸机屏幕/出厂的真实设备号，必须与管理后台「闸机」登记的一致 |
| 识别后在线验证 | 打开 |
| 可通行人员 | 已注册用户 |

## 五、前置检查

1. 服务器安全组/防火墙**开放后端端口**（调试 `8080`，正式 `443`）。
2. 浏览器访问 `http://59.110.11.215/api/health`（或 `https://api.example.com/api/health`）应返回健康。测试云走 Nginx 的 80 端口，不要在浏览器地址里加 `:8080`。
3. 管理后台「闸机」菜单新增设备，填真实 SN、名称、所属门店。
4. 测试云和正式服务器都使用 `prod`。人脸会真下发到闸机。

## 六、联调顺序

1. 后端部署、端口放行、`/api/health` 通。
2. 管理后台登记闸机 SN。
3. 闸机屏填 HTTP + WS + SN，管理后台 3 分钟内显示「在线」。
4. 在线验证通过后，再走「注册 → 购卡 → 到店认脸」全流程。

## 七、注意

- 测试云和正式服务器都是 `prod`，注册或后台录入的人脸会下发到在线闸机。
- 设备 SN 一旦不一致，闸机 `declare` 后会被服务端丢弃（日志只记一次）。
- 长连接路径固定 `/ws/gate`，别写错。

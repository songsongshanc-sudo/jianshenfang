## 0. 已确认的产品决定

竞品小程序是微信身份直接登录，首页有「开门码」，进店靠闸机扫二维码。自家产品按下面三条做。

1. **手机号登录，并采集人脸后才算注册成功。** 用户用手机号登录。手机号验证通过后立刻拍摄并上传人脸照片，这张照片交给闸机做人脸识别。上传并入库成功，才算注册登录成功，才发放会员编号。只验证了手机号、人脸还没成功的，不能购卡，也不能当作已登录。已经注册过的手机号再次进入时，人脸已在库里则直接登录，不用每次重拍。
2. **进店只做人脸识别。** 闸机认脸，不扫码。小程序不提供开门码，也不生成进店二维码。
3. **PC 管理端按账号看店。** 总账号看全部门店。每个门店单独的门店账号，只能看自己这家店。

手机号登录之后的购卡、未开通会员、门店服务，仍按本文后面的业务走。

## 1. 产品定位

做 24 小时无人值守健身房的用户端小程序：选店、购卡、人脸进店、门店服务、私教课包、报修投诉。运营侧用 PC 管理端看各店情况，并承接团购核销与加盟招商。

核心价值：

- 全天自助进出，无前台办卡。
- 卡种灵活：次卡、周期卡、限量卡，以及达到在籍天数后才解锁的卡。线上微信支付。
- 购卡时确认门店。确认文案写明购买后不能改门店。
- 门店服务自助化：WiFi、到店指引、器械报修、器械教程、失物、投诉、拥挤度。

5. 勾选「我已阅读并同意《会员协议》」。协议名可点，打开协议弹层。

8. 收银台：商户名带门店（例「凡铁德力电商城店（天津）」）、金额、付款方式可改（零钱或银行卡）、「使用密码」。

## 4. 核心业务流程

### 4.1 入场

进店只走闸机人脸识别。小程序不出示二维码。

```
手机号登录 → 上传人脸并入库成功（仅首次注册）
      → 购卡或核销团购券 → 获得该店有效权限
      → 到店，闸机识别人脸
      → 后端确认这个人在这家店的会员仍有效 → 开门并记流水
```

人脸已经入库但没有有效会员、或会员已过期：闸机能认出人，但不开门。未完成人脸注册的人，闸机没有可通行的身份。协议里的「带人进门扣天数」「尾随由会员担责」仍要能对应到具体会员，所以每条进店流水记到人。

### 4.2 购卡

```
首页卡片，或 我的-去购买 选卡
  → 确认层（门店、不可退、不可停、不可改店）
  → 勾选会员协议（可先阅读）
  → 按钮倒计时约 4 秒
  → 微信支付
  → 成功则开通该店时长；取消则停留原页并提示已取消
```

规则（确认层和协议已经写明的）：

- 购买时绑定当前门店，确认后不能改店。通卡是否例外，见第 9 节。
- 不能停卡。
- 默认不能退。若做特殊退款，按协议公式，每日扣除金额要可配置。
- 限量卡看剩余张数。
- 大会员、连续月卡未达天数时置灰。
- 单次卡「有效期 1 天」是自然日还是首次开门起 24 小时，协议没写，见第 9 节。
- 未过期再买一笔是叠加还是续期，成功页没拍到，见第 9 节。

### 4.3 团购核销

```
首页或我的 → 输入券码 → 立即核销 → 转成对应会员权限
```

本次是手输券码。核销成功发哪张卡，见第 9 节。卡列表里有一张名字就叫「月卡（美团/抖音购卡，好评有礼）」，和核销、好评赠卡可能是一套，但是关系没在页面上写明。

### 4.4 报修 / 投诉 / 失物

- 报修：可选扫设备码 + 必填描述 + 照片 → 提交 → 「报修反馈」看进度。
- 投诉：类型 + 描述 + 照片 → 提交 → 「投诉记录」看进度。
- 失物：列表按「全店 / 我丢失的 / 我拾取的」过滤；另有填写入口。物品有展示开关和解决状态。

### 4.5 私教课包

路径仍是买课包，不是日历约课：

```
预约教练 → 教练详情 → 课程详情 → 立即购买 → 支付
      → 我的课程出示核销码 → 教练扫码扣 1 节
```

课程「立即购买」之后的页面这次没走完。核销仍按第 9 节的默认假设：用户出示课时码，教练扫码扣 1 节。课时码只扣课，不能用来进店。进店只认闸机人脸。

### 4.6 加盟线索

```
我要开店 → 加盟申请 → 填写姓名、电话、资金、省市 → 提交申请
```

后台接线索即可。一期可以只留「关于我们」，见第 8 节。

## 5. 权限与拦截

### 5.1 小程序用户

「已登录」指手机号和人脸都已成功。只完成手机号的，视同未登录，只能继续人脸采集。

| 能力 | 未注册成功 | 已注册、未购卡 | 有效会员 |
| --- | --- | --- | --- |
| 浏览首页、卡种、加盟 | 允许 | 允许 | 允许 |
| 门店切换、地图、导航 | 允许浏览 | 允许 | 允许 |
| 人脸采集 | 手机号通过后必须完成 | 已完成 | 已完成 |
| 团购核销弹层、客服电话、在线客服 | 拦截到登录 | 允许 | 允许 |
| 购卡并支付 | 拦截到登录 | 允许 | 允许 |
| 闸机人脸进店 | 无注册人脸，开不了门 | 认得出人，会员无效则不开门 | 该店会员有效则开门 |
| 在线人数 | 不可见 | 仍提示开通会员后查看 | 可见数字（本次无会员，数字未验证） |
| WiFi 账号密码 | 不可见 | 可见，可复制 | 可见 |
| 首页门店指引 | 未登录会参数错误 | 可见步骤图 | 可见 |
| 器械报修、投诉建议、失物列表、好评赠卡、会员订单 | 拦截或空 | 允许 | 允许 |
| 大会员 / 连续月卡 | 置灰 | 未达天数置灰 | 达天数后可买 |

违规记录用于冒用他人身份进店、损坏器械等处置（扣天数、停卡、取消资格）。协议已经有扣天数和取消资格，具体判定见第 9 节。

### 5.2 PC 管理端账号

管理端只有两类账号。数据范围在服务端强制过滤，不靠菜单隐藏。

| 账号 | 能看的范围 |
| --- | --- |
| 总账号 | 全部门店。可按门店筛选。包含各店会员、订单、进店记录、工单、在线情况、闸机设备，以及门店、卡种、协议、支付和账号配置 |
| 门店账号 | 只看绑定的那一家店。看不到其他店，不能把请求里的门店改成别的店 |

规则：

- 一个门店可以有多个门店账号。一个门店账号只绑定一家店。
- 总账号创建、停用门店账号，并指定所属门店。门店账号不能创建总账号，也不能看到全品牌汇总。
- 门店账号可以处理本店报修、投诉、失物。不能改全品牌的卡种、价格、协议和支付配置。
- 人脸照片默认不在门店账号里展示。管理端只显示该会员「已采集」。总账号在排查识别问题时可以查看照片，并留下查看记录。

## 6. 数据对象

- 用户：openid（支付用）、手机号、昵称、头像、会员编号（人脸入库成功后才有）、注册状态、陪伴起始日、连续在籍天数、累计在籍天数、学生认证、人脸照片及闸机侧人脸 ID。
- 管理账号：总账号，或绑定一家门店的门店账号。
- 门店：编号、名称、省、市、地址、坐标、距离、营业状态、封面、WiFi 账号密码、公告、在线人数、客服时段和电话、投诉电话。
- 门店指引：门店、排序、图片、说明文字。
- 卡种：门店、名称、价格、展示文案（如每天最低价）、有效天数、库存、上下架、解锁条件（无 / 累计满 N 天 / 连续满 N 天）、是否通店、是否限量。
- 会员协议：版本、正文。下单记录用户已同意的版本。
- 订单：用户、门店、卡种或课包、金额、支付单号、状态（待支付、已支付、已取消）。
- 会员权限：用户 + 门店 + 起止时间 / 剩余次数。连续月卡要能表达「中断后失效」。
- 进店记录：用户、门店、时间、闸机。识别方式为人脸。
- 团购券核销：平台、券码、核销结果、转成的卡。
- 教练、课包 SKU、课时账户：同前。课包另有「适合人群」，和「课程内容」分开。
- 器械：编码（如 FT 开头）、所属门店、教程、视频。
- 报修单：设备编码、描述、照片、状态。
- 投诉单：类型（器械 / 卫生 / 教练 / 其他）、描述、照片、状态。
- 失物：门店、名称、发布人、展示范围、解决状态、丢失/拾取归属。
- 好评赠卡：平台（美团 / 抖音）、关联订单、领取状态。
- 加盟线索：姓名、电话、预计资金、省、市。
- 系统消息、违规记录。

## 7. 非功能

- 人脸照片只用于闸机识别，按敏感生物信息保存。门店账号默认看不到照片。
- 课时核销码如果做，要动态、短有效，并且不能当作进店凭证。
- 闸机认脸到开门，端到端控制在 2 秒内。
- 购卡按钮的协议倒计时在前端计时，避免连点直接支付。
- 切换门店后，卡种、教练、WiFi、指引、失物、客服电话都跟当前店。
- 公告、Banner、加盟文案、协议正文后台可配。
- 夜班电话按服务器时间切换，不要用手机本地时间单独判断。
- 空数据用空态。接口失败不要把「请求参数错误」原样弹给用户。
- 合规：用户协议、隐私政策、会员协议、特许经营信息（若做加盟）。竞品电话、备案号、WiFi 密码只作字段样例。

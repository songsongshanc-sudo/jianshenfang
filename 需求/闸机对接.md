# 闸机对接说明

厂商文档是「人脸识别设备 & 人脸速通门」。闸机自己认脸。我们提供 HTTP 接口给闸机调用，并用 WebSocket 或 MQTT 把人员照片和有效期下发给闸机。

原文：

- 总说明：腾讯文档《对接指南》
- HTTP：[HTTP设备接口](https://www.showdoc.cc/286732791253185?page_id=1858556223116740)
- 长连接：[设备长连接](https://www.showdoc.com.cn/2167329753987480/9766565168079257)，项目域名 `szeasco`

WebSocket 和 MQTT 二选一。第一期用 WebSocket。

## 1. 和现有代码的关系

厂商协议已经接上。购卡后才下发人脸。没买会员的人不会出现在闸机里。

管理端「模拟验码」仍走旧的 HMAC 接口 `/api/gate/v1/verify`，只给没有实机时验收开门规则。厂商闸机不调用这个地址。

已经接上的接口：

| 方向 | 接口 | 作用 |
| --- | --- | --- |
| 闸机 → 我们 | `POST /api/v1/verify_user` | 闸机已经认出 `user_id`，问现在能不能开门。这是开门决定 |
| 闸机 → 我们 | `POST /api/v1/record/face` | 通行记录。门往往已经开了，我们只记账，必须回成功 |
| 闸机 → 我们 | `POST /api/v1/stranger` | 陌生人、过期、不在通行时段。必须回成功，避免闸机反复重传 |
| 我们 → 闸机 | `declare` | 闸机连上后报自己的设备号，不用回复 |
| 我们 → 闸机 | `ping` / `pong` | WebSocket 心跳 |
| 我们 → 闸机 | `addUser` | 购卡后下发正脸和到期时间 |
| 我们 → 闸机 | `editUser` | 续期改到期时间，换脸覆盖同一会员编号 |
| 我们 → 闸机 | `setTime`、识别间隔、关闭验证失败放行 | 闸机每次连上后下发 |

不要用「设备在线比对」`/api/v1/recognition`。那个接口是闸机把照片发给我们做人脸比对，我们没有人脸算法。

`user_id` 用会员编号，不要用 `DL` 开头。`DL` 开头是闸机本机录入的人，会走陌生人记录。

会员能不能进店，用「识别后在线验证」实时问我们。同时把 `id_valid` 设成会员到期时间，闸机断网时也有一份到期时间。

## 2. 闸机上要做的设置

1. 长按主页，默认密码 `123456`，进入设置。
2. 公共设置里，设备对接方式选「开发者」。
3. 填我们的服务器地址、端口，通讯选 HTTP 或 HTTPS。
4. 长连接选 WebSocket：`WS` 或 `WSS`。子路径可以空。
5. 识别设置里打开「识别后在线验证」。人脸识别成功后才会调用 `/api/v1/verify_user`。
6. 可通行人员选「已注册用户」。选「任何人」时，记录会全部进陌生人接口。
7. 设置页能预览完整请求地址，核对接法是否正确。

开机连一次长连接。失败后 5 秒重连，之后每次多等 3 秒，最长 30 秒。网络变化会立刻重连。

## 3. 协议

### HTTP

闸机主动请求。地址是 `http(s)://域名:端口` 加上下面的路径。Body 是 JSON。

所有 HTTP 响应都带这三个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Result` | int | `0` 成功，其他失败 |
| `Msg` | string | 说明，只给排查，闸机不展示 |
| `Content` | object | 业务数据。在线验证时可以是 `{}` 或 null，不能是字符串 |

记录类接口如果 `Result` 不是 `0`，闸机会把记录存在本地，每 2 分钟重传，直到返回 `0`。记录接口收到后必须返回 `Result: 0`。

在线验证超过 5 秒没返回，闸机提示不可通行。这个超时可以用长连接指令 `setVerifyTimeout` 改。

### WebSocket 信封

下发指令包一层，不能只发 `data`：

```json
{
  "cmd": "to_device",
  "from": "消息编号",
  "extra": "",
  "to": "设备号",
  "data": { "cmd": "addUser" }
}
```

`from` 会在设备回复的 `to` 里原样带回，用来对上是哪一条指令。`extra` 也会原样带回。

设备回复：

```json
{
  "cmd": "to_client",
  "from": "设备号",
  "to": "消息编号",
  "extra": "",
  "data": { "cmd": "addUserRet", "code": 0, "msg": "" }
}
```

`declare` 和 `ping` 不套这层。

### MQTT 信封

和 WebSocket 二选一。协议心跳 1 分钟，QOS 0，Retain 0，Clean session 1，重连 10 秒。

| 方向 | 主题 |
| --- | --- |
| 我们发给某一台 | `iot/device/设备号` |
| 设备回复某一台 | `iot/service/deviceid` |
| 我们发给全部设备 | `iot/device/all` |
| 设备回复广播 | `iot/service/all` |

回复主题是字面量 `iot/service/deviceid`，不要写成 `iot/service/RT63715`。不要滥用 `iot/device/all`。

MQTT 消息体没有外层 `cmd` / `to`，主要是 `from`、`extra`、`data`。应用层心跳默认关闭。

### 照片

下发：

1. 压成 jpg，不超过 300KB，边长不超过 1280×720。厂商常用大约 50KB。
2. 做成完整 Base64，必须带前缀 `data:image/jpeg;base64,`。
3. 再做 UTF-8 的 URL 编码，放进 `face_template`。也可以直接传 http 图片链接。

闸机上传的识别照片是 URL 编码后的 Base64。先 URL 解码，去掉前缀，再 Base64 解码。启用厂商 OSS 后，照片字段会变成 URL。

### 签名

可以后做。先在设备「其它设置 → 高级 → Token」启用，或用指令 `setHttpToken` 下发。

HTTP 头，以及长连接的 `declare.signature` 里会有：

| 字段 | 说明 |
| --- | --- |
| `iot_sn` | 设备号 |
| `iot_timestamp` | 设备当前时间，秒 |
| `iot_nonce` | 随机数 |
| `iot_signature` | 签名 |

签名是把 `iot_sn`、token、`iot_timestamp`、`iot_nonce` 按字典序拼成一个字符串，再做 SHA1。厂商例子拼出来是 `1680083968T123456nonce6666toekn123`，其中随机数前面带了字面量 `nonce`。对接时用一台实机对一下这个例子。

记录正文里还有单独的 `signature`：成功记录是 `user_id`、token、`recog_time`；陌生人记录是 `real_user_id`、token、`recog_time`。同样排序后 SHA1。

### 长连接错误码

`data.code` 为 `0` 表示成功。常见失败：`1` 图片格式不对，`2` 缺图片，`3` 必填为空。`editUser` 时设备上没有这个人，返回 `6`。完整表在长连接文档「全局错误码」。

## 4. 本期要接的字段

### 4.1 识别后在线验证

`POST /api/v1/verify_user`

闸机本地认脸成功后调用。返回速度决定开门速度。

请求主要字段：`sn`、`user_id`、`type`、`confidence`、`recog_time`。刷卡时有 `card`。`type` 为 `3` 时 `user_id` 是身份证号。

响应：

| 字段 | 说明 |
| --- | --- |
| `Result` | `0` 可以通行。`1` 已过期。`2` 不在可通行时段。`3` 其他错误。`200` 闸机不做通行判断，只看要不要上传记录 |
| `Msg` | 可空。空则闸机按 `Result` 播内置语音 |
| `Content` | 对象，可为 `{}`。不要返回字符串 |
| `Content.is_upload_record` | `0` 不再上传记录，建议用这个，通行记录就在本接口里写。`1` 闸机还会再调上传识别记录 |
| `Content.voice_code` | `-2` 时播 `voice_text` |
| `Content.user_name` / `user_avatar` | 可选，显示在闸机结果页 |

本项目：按会员是否在有效期内、是不是这家店的会员决定 `Result`。记录在这里写入进店流水，`is_upload_record` 返回 `0`。

### 4.2 上传识别成功记录

`POST /api/v1/record/face`

已注册用户识别成功后上传。下面三种不走这里，改走陌生人接口：可通行人员设成任何人；本机录入且 `user_id` 以 `DL` 开头；人脸过了但不在有效期、不在通行时段或超过通行次数。

Body：`sn`、`Count` 固定 `1`、`logs` 数组。每条主要有 `user_id`、`recog_type`、`recog_time`、`gender`。`recog_type` 为 `face` 表示人脸。`pass_status`：`0` 已经开门，`1` 未开门。`photo` 是识别照片。

响应只需要 `Result: 0` 和 `Msg`。`Result` 为 `-2` 表示设备不存在。

若在线验证已经记账且 `is_upload_record` 为 `0`，这个接口主要用于补传。收到后仍返回成功，并按设备号加识别时间做幂等，避免重复流水。

### 4.3 上传陌生人记录

`POST /api/v1/stranger`

陌生人、任何人可通行、过期或不在时段。`logs.user_id` 在陌生人时固定为 `F1000001`。过期或未到时段时另有 `real_user_id`。`recog_type` 还可为 `expired`、`Impassable`。

同样必须返回 `Result: 0`。过期会员记一条未开门记录，不要补开会员。

### 4.4 客户端声明

闸机每次连接成功后发一次，不重发，除非重新连接。不要套外层信封，也不要回复。

```json
{
  "cmd": "declare",
  "type": "device",
  "sn": "设备号",
  "version_code": "1000",
  "version_name": "x.x.x",
  "ip": "设备IP",
  "timestamp": 1710000000
}
```

启用签名后带 `signature` 对象。用 `sn` 把连接和后台登记的闸机绑在一起。未登记的设备拒绝后续下发。

### 4.5 心跳

WebSocket 默认开启。设备每 30 秒发送：

```json
{ "cmd": "ping", "sn": "设备号", "timestamp": 1710000000 }
```

我们立即回复 `{ "cmd": "pong" }`。120 秒内没有 pong，设备断开并重连。不套外层信封。

### 4.6 下发人员 `addUser`

放在 WebSocket 的 `data` 里。设备上已有相同 `user_id` 会覆盖。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `cmd` | 是 | `addUser` |
| `user_id` | 是 | 会员编号，不要 `DL` 开头 |
| `name` | 是 | 姓名。没有姓名时用会员编号 |
| `face_template` | 人脸模式必填 | 按第 3 节编码的正脸 |
| `id_valid` | 是 | 会员到期，`yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm`。空字符串表示永久 |
| `effect_time` | 否 | 生效时间，空字符串表示立即生效 |
| `phone` | 否 | 手机号 |
| `user_type` | 否 | 不传就是正常用户。`10` 黑名单 |
| `mode` | 否 | `0` 立即录入并用长连接回结果，默认这个。`1` 先存本地，结果改走 HTTP |

设备回复 `data.cmd = addUserRet`，`code` 为 `0` 才算人脸入库成功。失败不要把用户标成已注册。

### 4.7 修改人员 `editUser`

设备上没有这个 `user_id` 时 `code` 为 `6`。`edit_mode` 传 `1`：只替换本次带上的字段。换照片时把新的 `face_template` 带上。

续期只改 `id_valid`。停卡把 `id_valid` 改成当前时间，或直接 `delUser`。

回复 `editUserRet`。

### 4.8 删除人员 `delUser`

```json
{ "cmd": "delUser", "user_id": "会员编号", "user_type": 0 }
```

`user_type` 不传默认 `0`，表示人脸下发的人。回复 `delUserRet`。

## 5. HTTP 接口全表

路径都相对闸机里配置的服务器地址。除说明类页面外，都是 POST，响应都用 `Result` / `Msg` / `Content`。

| 本期 | 名称 | 路径 | 作用 |
| --- | --- | --- | --- |
| 要 | 上传识别成功记录 | `/api/v1/record/face` | 已注册用户的通行记录。不回 `0` 会每 2 分钟重传 |
| 要 | 上传陌生人记录 | `/api/v1/stranger` | 陌生人、过期、不在时段 |
| 要 | 识别后在线验证 | `/api/v1/verify_user` | 本地认脸之后问能不能开门 |
| 否 | 上传人证记录 | `/api/v1/recordvisit` | 身份证访客 |
| 否 | 设备在线比对 | `/api/v1/recognition` | 闸机把照片发来，要我们做人脸比对 |
| 否 | 上传用户录入结果 | `/api/v1/updateEnrollResult` | `addUser` 的 `mode=1` 时回录入结果 |
| 否 | 设备录入自定义编号 | `/api/v1/addFace` | 在闸机屏幕上加人之前问服务器 |
| 否 | 设备请求删除用户 | `/api/v1/deleteUser` | 在闸机屏幕上删人之前问服务器 |
| 否 | 更新用户信息 | `/api/v1/user/inf_photo` | 闸机本地改了人，同步给服务器 |
| 否 | 同步人员数据 | `/api/v1/uploadFaceInfo` | 服务器向闸机要人员备份 |
| 否 | 密码开门在线验证 | `/api/v1/verify_password` | 密码开门。本项目不开门密码 |
| 否 | 上传位置信息 | `/api/v1/location` | 闸机 GPS。不回 `0` 会重传 |
| 否 | 门铃按钮 | `/api/v1/doorbell_press` | 按门铃。`Result 0` 也不会开门 |
| 否 | 首页访客二维码内容 | `/web_qrcode_url` | 闸机首页二维码指向的网址 |
| 否 | 二维码在线比对 | `/api/v1/qrcode_recognition` | 扫二维码问能不能过 |
| 否 | 二维码离线记录 | `/client_write_record` | 离线二维码产生的记录 |
| 否 | 健康码字段 | 无单独路径 | 识别记录里的 `health_code_color` |
| 否 | 二维码离线生成规则 | 无请求 | 二维码内容怎么编码 |

签名说明、更新说明、常见问题不是业务接口。签名规则见第 3 节。

## 6. 长连接指令全表

指令名是 `data.cmd`。设备成功回复一般是同名加 `Ret`，`code` 为 `0`。

| 版本 | `pushVersionInfo` / `pushUpdateRet` / `pushUpdateProgress` | 闸机把版本和进度推给我们 |

语音代码表、广告模式说明、指纹字段说明、更新说明、FAQ 是文档，不是指令。

## 7. 对接时的业务顺序

1. 后台登记闸机，记下设备号 `sn`。
2. 闸机按第 2 节指向我们的地址，并打开识别后在线验证。
3. 闸机连接 WebSocket，发送 `declare`。之后每 30 秒 `ping`。
4. 用户注册上传正脸后，我们发 `addUser`。`addUserRet.code` 为 `0` 才算注册完成，再发会员编号。
5. 购卡或续期成功，发 `editUser` 更新 `id_valid`。
6. 用户到店，闸机本地认脸，调用 `/api/v1/verify_user`。有效会员返回 `Result: 0`，并在这里写进店记录。
7. 若闸机仍上传 `/api/v1/record/face` 或 `/api/v1/stranger`，返回 `Result: 0`。同一设备、同一人、同一秒的记录不要重复记账。
8. 会员到期或作废，发 `editUser` 或 `delUser`。

课时码仍然不能开闸机。课时码不是这个协议里的 `user_id`。
